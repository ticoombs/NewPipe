## UploadCadenceAnalyzer EWMA pinned values

- Added `UploadCadenceAnalyzer` as pure Kotlin logic with injected clock only; no `OffsetDateTime.now()` calls in the analyzer.
- TDD red was confirmed by compiling `UploadCadenceAnalyzerTest` before the analyzer existed, producing unresolved-reference errors.
- Pinned EWMA case uses intervals `[7, 7, 7, 14, 7]` from newest-to-oldest upload dates. With alpha `0.3`: seed `7`, then `7`, `7`, `9.1`, `8.47`, so `roundToInt()` predicts `8` days.
- Weekday detection uses `ZoneId.systemDefault()` and tie-breaks same-count weekdays by most recent occurrence in the sorted sample, matching the state machine requirement for primary weekday selection.
- Weekday tests pin UTC as default timezone except the timezone-boundary test, which temporarily switches to `America/New_York` to prove local weekday conversion is used.

## T?: Pref-gating nextUpdate in SubscriptionViewModel

- `SubscriptionWithUpdateInfo` is a Kotlin `data class`, so `it.copy(nextUpdate = null)` works cleanly for gating.
- `ChannelItem` is NOT a data class (regular `class` with private val `nextUpdate`) — gate at the data layer (`SubscriptionWithUpdateInfo`) BEFORE constructing `ChannelItem`, not after.
- Pattern used: `BehaviorProcessor<Boolean>` seeded from current pref value, fed by an `OnSharedPreferenceChangeListener` registered on `PreferenceManager.getDefaultSharedPreferences`.
- Combined with subscription Flowable via `Flowable.combineLatest(subs, prefProcessor.distinctUntilChanged(), ::Pair)` then mapped.
- Listener unregistration happens in `onCleared()` to avoid leaks (mirrors `FeedFragment.kt:107` style).
- Extracted the pure transformation into a `@VisibleForTesting @JvmStatic` companion-object function `gateNextUpdateBySmartScheduling(Flowable<...>, Flowable<Boolean>): Flowable<...>` — testable WITHOUT Robolectric or Room (pure Rx).
- Tests use `Flowable.test()` (RxJava3 TestSubscriber) + `awaitCount(n)` + `.values()` for synchronous assertions; `BehaviorProcessor.onNext` to simulate pref toggles.
- `SubscriptionEntity` has a no-arg constructor (all fields default) — easy to build test fixtures without `ChannelInfo`.

## 2026-05-19 — Dialog theme attr fix

NewPipe's app theme is AppCompat-only (Theme.AppCompat.DayNight.NoActionBar
ancestry), so Material3/MDC attrs like `?attr/colorOnSurface`,
`?attr/colorOutline`, `?attr/textAppearanceTitleMedium`,
`?attr/textAppearanceCaption` are NOT available — using them in any layout
inflated against the app theme will crash at runtime with
`UnsupportedOperationException: Failed to resolve attribute`.

Safe replacements proven in this codebase:
- `?android:attr/textAppearanceMedium` instead of `?attr/textAppearanceTitleMedium`
- `?android:attr/textColorPrimary`     instead of `?attr/colorOnSurface`
- `?attr/separator_color`              instead of `?attr/colorOutline`
- `@style/TextAppearance.AppCompat.Caption` instead of `?attr/textAppearanceCaption`

When authoring new dialog layouts, grep existing dialogs for theme attrs
already in use (e.g. `dialog_feed_group_create.xml`,
`dialog_playback_parameter.xml`) rather than copying from Material3
docs/examples.
